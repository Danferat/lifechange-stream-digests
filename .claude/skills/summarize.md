# Скилл: summarize

Генерирует из `summary_source.md`:
- `summary_intermediate_notes.md` — средняя (N строк, по одной на каждый блок, компактно)
- `summary_short.md` — короткая (19-24 строки, ключевые моменты)
- `summary.md` — длинная (N строк, по одной на каждый блок, развёрнуто)
- `summary_mentioned_materials.md` — реальные инструменты/сервисы, упомянутые в стриме

`summary_short.md` не привязана построчно к блокам — её таймкоды должны быть точны относительно
реального момента тезиса в записи (см. Шаг 4), а не скопированы из `summary.md`/
`summary_intermediate_notes.md`. Совпадение таймкодов между файлами — не цель само по себе;
цель — точность каждого таймкода по отдельности.

Затем запускает build-скрипты и проверяет финальные артефакты.

Использовать при любой просьбе сделать выжимку, сводку, summary стрима в проекте
`<project-root>`.

## Вызов

```
/summarize [work_dir] [stem]
```

Аргументы опциональны — если не указаны, скилл сам находит цель.

---

## Шаг 1. Найти цель

Если `work_dir` и `stem` не указаны:

- Найти в `work/` все папки, где есть `groq_outputs/<stem>_summary_source.md`,
  но нет хотя бы одного из: `summary_short.md`, `summary.md`, `summary_intermediate_notes.md`.
- Если одна такая папка — взять автоматически.
- Если несколько — спросить пользователя какую обрабатывать.
- Если таких папок нет — сообщить что все стримы уже обработаны.

## Шаг 2. Прочитать исходники

Прочитать оба файла:

- `{work_dir}/groq_outputs/{stem}_summary_source.md` — N строк сырой транскрибации
- `{work_dir}/groq_outputs/{stem}_meta.json` — взять `summary_source_lines` (это N)

Каждая строка source имеет формат: `HH:MM:SS  <сырой текст блока>`.

## Шаг 2б. Извлечь начало каждого блока механически (обязательно)

Блоки нарезаны по чистому времени (4 минуты), а не по смыслу - тема почти всегда перетекает
через границу блока, последнее предложение блока N и первое предложение блока N+1 часто об одном
и том же. Если source длинный и не помещается в один `Read`, легко приписать факт из конца/середины
блока N таймкоду блока N+1, потому что тема "ощущается" как относящаяся к следующему блоку.
Полагаться на общее впечатление от прочитанного текста для этого недостаточно - нужна механическая
сверка.

Перед тем как писать `summary.md` и `summary_intermediate_notes.md`, извлечь начало каждого блока
отдельной командой:

```bash
python3 -c "
import re
with open('{work_dir}/groq_outputs/{stem}_summary_source.md', encoding='utf-8') as f:
    content = f.read()
blocks = re.split(r'(?m)^(?=\d{2}:\d{2}:\d{2}  )', content)
for b in [x for x in blocks if x.strip()]:
    print(b[:8], '|', b[10:].strip()[:400].replace(chr(10), ' '))
"
```

Каждая строка `summary.md`/`summary_intermediate_notes.md` должна описывать факт, буквально
присутствующий в первых 1-2 предложениях извлечённого фрагмента её блока. Если факт кажется важным,
но в выведенном фрагменте его нет - либо это факт следующего блока (проверить его фрагмент), либо
в текущем блоке нужно выбрать другой, более ранний факт.

## Шаг 3. Сгенерировать summary_intermediate_notes.md

Записать в `{work_dir}/summary_outputs/{stem}_summary_intermediate_notes.md`.

Правила:
- Ровно N строк — по одной на каждый блок из source, в том же порядке
- Формат: `HH:MM:SS  Короткое описание` (тот же таймкод из source, два пробела, строго HH:MM:SS)
- ВАЖНО: таймкод здесь ВСЕГДА в формате `HH:MM:SS` (с ведущими нулями) — этот файл читает build_intermediate_digest.py через строгий regex, менять формат нельзя
- Описание: компактно, явная тема блока — что конкретно обсуждалось
- Без точки в конце строки
- Без markdown-маркеров, скобок, кавычек, эмодзи

## Шаг 4. Сгенерировать summary_short.md

Записать в `{work_dir}/summary_outputs/{stem}_summary_short.md`.

Это навигация по стриму, а не лента интересных фактов. Каждая строка = смысловой блок стрима,
таймкод = момент, когда этот блок реально начинается.

Порядок работы (обязательно, до написания строк):

1. Пройти стрим целиком (по `summary_source.md` или `transcript.txt`) и выписать точки, где
   меняется тема: явные переходы ("давайте перейдём к", "переходим к нашей любимой", "значит,
   по поводу", "что ещё у нас"), смена спикера-ведущего темы, начало демонстрации, начало блока
   вопросов. На этом шаге таймкоды приблизительные - это только черновой список тем.
2. ЗАПРЕЩЕНО брать финальный таймкод на глаз из `transcript.txt` (там строки склеены по ~30-40
   секунд, и позиция фразы внутри строки не равна её реальному времени) или пересчитывать его в
   уме. Для каждой темы из шага 1 обязательно вызвать `scripts/segment_lookup.py`, который читает
   точные `start`/`end` из `{stem}_segments.json` (сегменты Whisper, ~5-15 сек):
   ```bash
   python3 scripts/segment_lookup.py "{work_dir}" {stem} --search "ключевая фраза темы"
   # или, если ключевую фразу трудно угадать:
   python3 scripts/segment_lookup.py "{work_dir}" {stem} --around ЧЧ:ММ:СС --window 60
   ```
   Взять таймкод из строки `[NNNN] <таймкод>  <текст>`, где эта тема действительно начинает
   звучать - не первое случайное совпадение подстроки (`--search` может дать ложные срабатывания
   внутри других слов, проверяй текст рядом), а первый сегмент, где ведущий явно заговорил об
   этом предмете. Готовый таймкод из вывода скрипта копируется в файл как есть, без ручной
   конвертации.
3. Полученный список тем и есть строки `summary_short.md`. Если тем больше 24 - объединить
   соседние мелкие темы одного смыслового кластера в одну строку через запятую (обычно те, что
   расположены ближе 60-90 секунд друг к другу); если меньше 19 - разбить длинные темы по
   подтемам, снова находя точный старт каждой подтемы через `segment_lookup.py`.

Типичные ошибки:
- Надёргать 20 ярких фактов и расставить их таймкоды - тогда карта стрима не собирается: начало
  темы теряется, а таймкод указывает в середину блока.
- Взять таймкод фразы, которая звучит понятнее или "цитируемее", вместо фразы, где тема реально
  начинается (даже если она менее выразительна). Таймкод = вход в тему, а не punchline темы.

- ПЛОХО (выдержка из середины блока): `19:04 Kimi хорош по цене-качеству`
- ХОРОШО (начало блока): `17:55 переход к AI: ажиотаж вокруг Kimi, продажи новых подписок отключены`

Правила формата:
- 19–24 строки (не меньше, не больше)
- Не более 4000 символов суммарно
- Формат таймкода: `MM:SS` когда часов нет (HH=00), `H:MM:SS` когда есть (HH≥01). Примеры: `00:00:00` → `00:00`, `00:11:46` → `11:46`, `01:02:45` → `1:02:45`
- Каждая строка: `<таймкод> Суть` (один пробел после таймкода)
- Таймкод берётся НЕ из `summary_source.md` (там шаг 4 минуты, слишком грубо), а из
  `{work_dir}/groq_outputs/{stem}_transcript.txt` — там мелкая сегментация (обычно 30-40 секунд
  на строку). Найти сегмент, где конкретный тезис впервые чётко звучит, и взять таймкод оттуда
- Если один блок source содержит два факта, разнесённых по времени больше чем на ~60-90 секунд —
  не сжимать их в одну строку с одним таймкодом: либо оставить только главный факт, либо развести
  по двум строкам с их настоящими таймкодами
- Строка = сжатый факт, как газетный заголовок. Только суть — без объяснений, без "потому что", без контекста
- Если в блоке одно событие — одна фраза. Если два важных одновременно — через запятую
- Запрещены: объяснения почему это важно, вторые части после тире с контекстом, связки "потому что / из-за чего / именно поэтому"
- Запрещены глаголы-описания действия ("Разбираем", "Показываем", "Объясняем", "Анонсируем", "Говорим", "Переходим") в начале строки
- ПЛОХО (полотно): `200+ крипто-компаний публично попросили Clarity Act - открытое признание что индустрия задыхается без регулирования`
- ПЛОХО (тема, не факт): `индустрия обсуждает Clarity Act`
- ХОРОШО (сжатый факт): `индустрия требует принятия Clarity Act`
- ПЛОХО (полотно): `AI это "изобретение мозгов" - масштаб больше интернета, уже вопрос нацбезопасности`
- ХОРОШО (сжатый факт): `AI превратился в вопрос нацбезопасности`
- ПЛОХО (полотно): `S&P закончил 9 недель роста сливом на 2 трлн, IPO SpaceX создаёт sell-event - тряска ожидается по всему рынку`
- ХОРОШО (два события одновременно): `S&P слил 9 недель роста, IPO SpaceX создаёт sell-event`
- Без точки в конце строки
- Без markdown-маркеров, скобок, кавычек, эмодзи
- Объединять мелкие переходы в одну строку если они в одном смысловом кластере
- Выбирать значимые моменты, не дублировать каждый таймкод из source
- Без заголовков разделов и пустых строк - сплошной список строк

## Шаг 4б. Сгенерировать summary.md (длинная выжимка, обязательно)

Записать в `{work_dir}/summary_outputs/{stem}_summary.md`.

Правила формата:
- Ровно N строк - по одной на каждый блок из source, в том же порядке
- Формат таймкода: `MM:SS` когда часов нет (HH=00), `H:MM:SS` когда есть (HH≥01) — то же правило что в summary_short.md
- Формат строки: `<таймкод> Суть` (один пробел после таймкода)
- Таймкод берётся из source (тот же, что в блоке) — здесь точность НАМЕРЕННО ограничена стартом
  4-минутного блока (ровно N строк на N блоков это жёсткое требование), в отличие от
  `summary_short.md`, где таймкод ищется по мелкой сегментации `transcript.txt`
- Строка должна описывать то, что действительно звучит ближе к началу блока, а не тему,
  которая раскрывается только к его концу (иначе привязка к таймкоду блока станет неточной) -
  свериться с фрагментом из Шага 2б, не с общим впечатлением от текста
- Строка = сжатый факт, как газетный заголовок. Только суть — без объяснений, без "потому что", без контекста
- Если в блоке одно событие — одна фраза. Если два важных одновременно — через запятую
- Запрещены: объяснения почему это важно, вторые части после тире с контекстом, связки "потому что / из-за чего / именно поэтому"
- Запрещены глаголы-описания действия ("Разбираем", "Показываем", "Объясняем", "Анонсируем", "Говорим") в начале строки
- ПЛОХО (полотно): `AI это "изобретение мозгов" - масштаб больше интернета, уже вопрос нацбезопасности`
- ХОРОШО (сжатый факт): `AI превратился в вопрос нацбезопасности`
- Каждая строка — конкретный факт с именами, цифрами, названиями если они есть в блоке
- Без точки в конце строки
- Без markdown-маркеров, скобок, кавычек, эмодзи
- Дефис "-" вместо длинного тире "—"
- Названия: ЛАЙФЧЕЙНДЖ (нескл.), Лайфчейнджер/Лайфчейнджеров (склоняется)
- Блоки технического старта (проверка звука, представления) - описывать кратко, не раздувать

## Шаг 4в. Сгенерировать summary_mentioned_materials.md (обязательно)

Записать в `{work_dir}/summary_outputs/{stem}_summary_mentioned_materials.md`.

Это список реальных инструментов, сервисов, проектов и материалов, упомянутых именно в этом
стриме (source), а не статичный список тем - build_final_digest.py подставит его в блок
"Полезные ссылки из чата" вместо старого автоматического поиска по фиксированному словарю.

Правила:
- Одна строка на каждый упомянутый инструмент/сервис/проект, формат `• Название`
- Только то, что реально названо в source (конкретные имена: Alchemy, DexScreener, GMGN,
  Robinhood Chain, Dune и т.д.) - не подставлять темы, которых не было
- Без дублей, без URL (их в аудио нет), без markdown-разметки, без кавычек
- Если ничего конкретного не упомянуто - оставить файл с одной строкой
  `• Не найдено явных инструментов, сервисов или тем для отдельного поиска`

## Шаг 5. Запустить build-скрипты

Выполнить последовательно из корня проекта:

```bash
python3 scripts/build_intermediate_digest.py "{work_dir}" {stem}
python3 scripts/build_final_digest.py "{work_dir}" {stem} --limit 12
python3 scripts/validate_outputs.py "{work_dir}" {stem} --check-final
```

## Шаг 6. Финальный отчёт

Вывести:
- Количество строк в каждой из трёх выжимок (короткая / средняя / длинная)
- Пути к файлам для выгрузки: `_summary_short_with_links.md` и `_summary_with_links.md`
- Результат валидации (`VALIDATION_OK` или описание ошибки)
